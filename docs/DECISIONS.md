# Build Decisions Log

- **.upstream reference clone** kept outside the repo (at /tmp during the initial build) rather than committed — 35MB of reference material; BUILD_PROMPT's intent (a reference copy) is met without bloating the repo. Re-clone with `git clone --depth 1 https://github.com/santifer/career-ops.git .upstream` when needed (gitignored).
- **Scripts moved to `engine/`** per ARCHITECTURE §2. All ported scripts had their repo-root anchor patched (`dirname(__dirname)` style) and providers/plugins import paths adjusted. Provider board modules live under `providers/ats/`; their `_helper` imports were rewritten to `../`.
- **`test-all.mjs` rewritten lean** rather than ported: upstream's 1,100-line suite is deeply coupled to the job-search tree (CV/PDF/apply/interview checks). The new suite keeps: syntax sweep, unit-test runner, paths-coverage, required-files, brand-purge guard, no-send-code guard, no-absolute-paths guard. Upstream's liveness/PDF deep tests to be re-added selectively in M2/M3 when those subsystems are reworked.
- **Runner scripts** (gemini/openai/ollama/openrouter eval) NOT ported in M0 — they embed the job-evaluation prompt. To be recreated against the outreach grading rubric in M3+.
- **`portals.yml` name kept** for the scanner's watch config in M0 (scan.mjs reads it); M2 renames to watchlists/icp wiring when the signal layer lands.
- **Job-search scripts skipped**: cv-sync-check, application-answers, prepare-application, match-star, classify-tier, generate-cover-letter/latex, process-quality, agent-inbox, archive-posting. `role-matcher.mjs` WAS ported (dependency of dedup/find/merge fuzzy matching).
- **Updater repo constants** point at `haris-hk/outreach-ops` (placeholder until the GitHub repo name is confirmed); checker degrades to `offline`/`no-remote-version` silently while the remote doesn't exist.
- **Sandbox note:** the Cowork mounted folder forbids file deletion, so the build runs in a scratch dir and is synced into the folder per milestone; run `git init` locally if the .git dir doesn't survive the sync.
- **M2 — Signal layer split:** the ported ATS job scanner survives verbatim as `engine/scan-ats.mjs` (individual-mode job discovery + raw layer); the new `engine/scan.mjs` is the signal orchestrator (icp.yml segments → provider fan-out → trigger match → inbox). Board modules stay in `providers/ats/`; top-level `providers/*.mjs` are Signal providers.
- **M2 — funding provider limitation:** no reliable free structured funding API exists; `providers/funding.mjs` is a preset over user-supplied funding-news RSS feeds with round parsing, returning [] cleanly when unconfigured. Paid structured sources (Crunchbase-class) belong in a plugin.
- **M2 — plugin hooks extended:** `HOOK_KINDS` gained `enrich`, `verify`, `replies` (upstream had provider/ingest/search/notify/export). Explorium (enrich) and Hunter (enrich+verify) ship as thin-client scaffolds; endpoint field names may need adjustment per API plan.
- **M2 — states single-source:** verify-pipeline and normalize-statuses now derive canonical statuses + aliases from `templates/states.yml` at runtime instead of inlined arrays (they had drifted copies upstream).
- **M2 — header aliases unified:** verify-pipeline's inlined column-alias table replaced with the grade/dossier/contact/segment/channel-aware version from tracker-parse.
- **M3 — patterns split:** new `engine/patterns.mjs` mines `data/outcomes.tsv` (reply/win rates by segment/channel/angle/variant/timing + data-driven observations); the ported ledger-status analyzer survives as `engine/analyze-patterns.mjs`. Suggestions are surfaced by patterns.mjs but only ever APPLIED via review-mode human approval.
- **M3 — gmail plugin reworked read-only:** hooks [replies], gmail.readonly scope only, metadata search only (bodies never fetched). Orchestrated by `engine/check-replies.mjs`, which collects active sequences from outcomes.tsv + addresses from the enrich cache and logs `replied` events idempotently.
- **M3 — cadence filename kept:** `followup-cadence.mjs` name retained (tests + exports reference it) instead of ARCHITECTURE's `cadence.mjs`; npm alias `npm run cadence` covers the spec name. Reply-aware next-action logic lives in `outcomes.mjs nextAction` (single place that knows terminal events).
- **M3 — dossier renderer:** dependency-free markdown→HTML converter + the upstream Playwright page.pdf pattern. In environments without chromium it degrades to HTML output with a note (exercised in tests); PDF path requires `npx playwright install chromium`.
- **M4 — web/ deferred:** the upstream Next.js UI is ~100 files of deeply job-search-coupled TSX (apply forms, CV editor). A faithful lead-board re-skin is post-launch work; the Go TUI covers the visual-board need at launch (re-skinned tabs: ALL / PRIORITY ≥4.2 / PIPELINE / SENT / CALLS / REPLIED / NURTURE-DQ / LOST; NormalizeStatus retargeted to the lead lifecycle). Tracked as a launch-follow-up.
- **M4 — batch verification scope:** resume/pause/retry state machine exercised via `--dry-run` on a 10-fixture input (live workers need a `claude -p` session, unavailable in the build sandbox). The runner's own state/lock/retry logic is upstream-tested code, unchanged except path/prompt retargets.
- **M4 — TUI Go compile not run in sandbox** (no Go toolchain); edits were confined to label arrays, one added const, a threshold literal, and a string-matched rewrite of NormalizeStatus. Run `npm run build:dashboard` locally to confirm.
- **M4 — publish step prepared, not executed:** repo creation/push needs the owner's GitHub auth. Updater constants point at haris-hk/outreach-ops (pending confirmation) and degrade silently while the remote doesn't exist.
